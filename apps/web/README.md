# Neuroset Web

Статический веб-чат с OpenAI-совместимым API `/chat/completions`. Работает на GitHub Pages без собственного сервера. Интерфейс на русском, React + TypeScript + Vite.

## Локальный запуск

Нужен Node.js 24 LTS.

```powershell
cd apps/web
npm ci
npm run dev
```

Откройте адрес, который выведет Vite (обычно `http://127.0.0.1:5173`).

Для проверки готовой сборки:

```powershell
npm run build
npm run preview
```

## GitHub Pages

1. Загрузите проект в репозиторий GitHub. Файл `apps/web/package-lock.json` должен быть в репозитории.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. Отправьте изменения в `main` / `master` или запустите **Actions → Web · GitHub Pages → Run workflow** для основной ветки.
4. После успешного задания `deploy` сайт будет доступен по адресу `https://<username>.github.io/<repository>/`. Точная ссылка появится в задании и разделе Pages.

Workflow проверяет тесты и собирает только веб-приложение. Для основной ветки с другим именем измените `branches` в `.github/workflows/pages.yml` или запускайте workflow вручную. Пути к ресурсам относительные, поэтому работают и домен пользователя, и подпапка репозитория. Содержимое `dist` также можно разместить на любом статическом HTTPS-хостинге.

## Подключение API

Нажмите **Подключить модель** или **Настройки**:

- **Адрес API**: например `https://api.openai.com/v1`. Допускается полный адрес `https://provider.example/v1/chat/completions`; префиксы провайдера сохраняются.
- **API-ключ**: ключ провайдера. Можно оставить пустым, если API не требует авторизации.
- **Модель**: точный ID модели. Кнопка **Загрузить** получает список через `GET /models`; ручной ввод работает независимо от поддержки этого метода.
- При необходимости задайте системную инструкцию, температуру, `max_tokens` и режим потоковых ответов. Пустые числовые поля не передаются в API.

Приложение отправляет `POST /chat/completions` с `model`, `messages`, `stream` и заголовком `Authorization: Bearer <key>`, если ключ задан. История текущего чата передаётся как контекст. Поддерживаются SSE (`text/event-stream`) и обычный JSON. Кнопка остановки отменяет запрос; незавершённый ответ остаётся в истории. Максимальное ожидание ответа — 5 минут.

GitHub Pages размещает статические файлы и не проксирует запросы. API должен быть доступен по HTTPS и разрешать CORS для источника сайта, например `https://<username>.github.io` (без пути репозитория). Для запросов с ключом сервер должен отвечать на preflight `OPTIONS`, разрешать методы `POST, GET, OPTIONS` и заголовки `Authorization, Content-Type`. Если провайдер не разрешает браузерные запросы, понадобится его браузерный шлюз или свой прокси; это нельзя исправить настройкой статической страницы.

## Возможности и данные

- Потоковые ответы, Markdown, таблицы, подсветка и копирование кода.
- Создание, поиск по сообщениям, переименование и удаление чатов.
- Редактирование вопроса с заменой последующей истории, повтор последнего ответа, экспорт текущего чата в Markdown.
- Адаптивный интерфейс, тёмная и светлая темы. На компьютере Enter отправляет сообщение, Shift + Enter добавляет строку; на телефоне отправка кнопкой.
- Чаты, черновики и настройки хранятся в `localStorage` данного сайта. Они не синхронизируются между устройствами и удаляются при очистке данных сайта. Нативная SQLite-история автоматически не переносится.
- По умолчанию ключ хранится в `sessionStorage` до закрытия вкладки. Опция **Запомнить ключ** сохраняет его в `localStorage` без шифрования. Ключ не попадает в сборку, репозиторий или экспорт чата.
- HTML из ответов не исполняется. Изображения из Markdown отображаются ссылками.

Веб-версия предназначена для текстового общения. Нативные агенты, локальные инструменты, Python, RAG и выполнение команд в неё не входят.

## Проверки

```powershell
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Тесты используют локальные подмены API: платные запросы и реальные ключи не требуются. Браузерные проверки покрывают потоковые ответы, контекст, ошибки, отмену, редактирование, повтор, копирование кода, историю после перезагрузки, мобильное меню, темы и загрузку из подпапки.
